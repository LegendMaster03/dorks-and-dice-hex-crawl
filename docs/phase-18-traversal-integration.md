# Phase 18 — traversal integration and release gates

**Status:** Independently reviewed, corrected, and merged to main through PR #74 at 134147fa42302f2fcd6bda76508bd6ad326ce1e5. The original review-candidate notes below describe the implementation baseline; deployment and signed-in tester smoke status are not established by this document.

**Baseline:** main at c3c16e9e4ab09c2006162fc69079aef0ca2aa86e; PostgreSQL schema 10 and campaign procedure schema 1.3. Only the Hex Crawl repository has changed.

## Implemented foundations

### One authoritative geometric crossing resolver

- PeriodicCellTraversal identifies the exact world-qualified cell, current world-coordinate position, optional entry interface and prior cell, chosen heading, and optional selected exit interface. Cursor format version 1 is validated on read.
- PeriodicCellTraversalGeometry crosses only an atomic WorldCellBoundary from PeriodicWorldTiling and verifies its reciprocal. Subdivided polygon sides are not treated as whole side indexes, and heading is not an interface ordinal.
- A vertex tie, outward departure through an unselected side, selected inward/tangential departure, ambiguous coincident course, or unreliable boundary resolution requires adjudication; no arbitrary neighbor selection.
- PeriodicTraversalExecution handles physical-distance budgets and discrete cell-step budgets through this same geometry kernel. One cell step is one successful atomic boundary crossing. The actually traveled route length is measured; no equal-distance assumption or cell counting is used for physical travel. Physical movement requires the tiling's explicit calibration; uncalibrated cell-step movement has no fabricated physical distance.
- Travel can stop at a boundary, resume, traverse several cells, or pause after one crossing for a review. Bounded crossing enumeration prevents unbounded zero-progress loops.

### Materialized procedure semantics

- Legacy movement handler version 1 and HexProgressPolicy remain intact for saved hex expeditions and abstract-hex sessions; original six-direction veering and partial-progress factors have not been reinterpreted.
- Movement handler version 2 explicitly separates ContinuousDistance from CellSteps and prohibits legacy hex-progress factors. It binds through GenericProcedureRuntime.Bind from the pinned CampaignProcedure, not a preset key.
- CrawlRuntimeEngine.ResolveCellTravel invokes the same domain geometry executor and requires a version-2 procedure whose canonical D-symbol matches the world's accepted quotient.
- CrawlRuntimeEngine.AdvanceCellWatch now integrates version-2 cell travel with the pinned procedure's interval duration and encounter cadence, qualified event/history sequencing, angular navigation outcomes, resolved veer, lost recognition, double-back boundary stopping, encounter occurrence/resolve, boundary review, deterministic watch completion, and physical-distance accounting. Ambiguous courses pause rather than fabricating a neighbor; ResolveCellCourse validates an explicit atomic exit and the actual outgoing ray before saving the decision.
- The generalized entry points are a **typed watch adapter inside the same partial CrawlRuntimeEngine**, not an independently maintained runtime. Shared watch-start interval/encounter cadence binding, encounter occurrence-ID/event metadata, DM override detection/note precedence, lost-recognition validation, a single encounter-time window slicer, time helpers and event collector are reused. The hex-specific `AdvanceCore` and cell-specific `AdvanceCellWatch` still have separate geometry-sensitive orchestration; independent review must assess whether any remaining duplication constitutes a divergent mechanic. Legacy `CrawlRuntimeEngine.Advance` still rejects version-2 movement.

### Runtime state and persistence

- CellExpeditionState is a distinct non-axial runtime state; it never stores fabricated Q/R coordinates. Its only authoritative position and actual course are in PeriodicCellTraversal. CellActiveWatchState retains intended course, elapsed/remaining watch time, encounter schedule and pending decision without duplicating the authoritative position.
- Uncalibrated physical travel totals are represented as unknown (null), rather than an arbitrary physical scale.
- RuntimeStateSnapshot gains the additive CellSpatial discriminator and cell-state fields. Existing Spatial and NonSpatial read/write representations are retained. New optional fields are omitted when null to avoid rewriting older legacy JSON structure.
- Pending encounters and runtime events can carry a qualified WorldCellId, and generalized movement events can carry reciprocal atomic interface identities. Historical hex event values and fields are unchanged.
- EnvironmentContextResolver uses the authoritative current cell for feature intersections and cell-scoped annotations, while preserving legacy hex-scoped annotations for hex worlds. No semantic environment state is inferred from D-symbol identity.
- PlayerKnowledgeState optionally stores world-qualified KnownCells, with legacy KnownHexes unchanged and the new field omitted from old snapshots. Generalized starts can select an existing presentation policy and initialize the actual starting cell and explicitly eligible visible subjects without revealing hidden locations. PresentationKnowledgeProjection applies actual cell-entry events according to policy; DM-controlled views never reveal cells automatically.
- Existing owner/version-protected DiscoverAsync now accepts cell-world expeditions and reuses the same semantic feature/location validation and knowledge updates. Cell discovery events carry WorldCellId, never surrogate hex coordinates. A separate cell-world composition adapter attaches location/linked-scene snapshots to encounter triggers, validates keyed encounters against the real current-cell polygon, and appends precisely scoped location discovery events. Automated knowledge revelation obeys presentation policy. These world effects commit in the same optimistic-concurrency transaction as movement.
- Both the direct effect service and the journey aggregate-consequence transition now support structured time delays on cell expedition clocks. They defer such a delay while a watch is active, advance only authoritative elapsed time otherwise, and retain the existing applied-consequence deduplication path. Neither transition fabricates movement, cell changes, or distance.
- The existing journey-process clock, completed-watch event/opportunity integration, relevant-travel pause gates, and forced-travel/survival accounting now accept authoritative cell expedition time. The cell application service invokes these shared hooks in the same optimistic-concurrency mutation as movement, and rejects activity assignments that differ from the authoritative party/watch snapshot.
- Ambiguous course pauses are now mandatory: ordinary watch retry cannot silently clear `CellCourseAdjudicationRequired`; only a geometrically verified `ResolveCellCourse` transition may resume. Active encounter state is also validated against its qualified cell and watch.
- Shared lost-recognition validation now refuses reorientation unless the navigator explicitly recognizes being lost in both legacy hex and generalized cell watches. Mid-watch cell heading changes emit qualified `DirectionChanged` audit events; an encounter-paused cell snapshot without its pending occurrence is rejected rather than restored into an unresolvable pause.
- Cell-scoped environment annotations now round-trip through the standard world environment HTTP GET/PUT contracts without dropping their tiling-qualified cell address. Effective environment fact provenance also exposes its actual cell identity. Frontend environment types admit `Cell` scopes and qualified identities without enabling the old hex authoring UI for nonhex worlds.
- The existing read-only workbench API now projects qualified cell identity, traversal cursor, exact position, intended/actual heading, cell encounter identity, KnownCells and reciprocal interface event metadata.
- Backend-only, owner-scoped cell APIs have distinct `POST /api/overworlds/{overworldId}/cell-expeditions` for pinned saved version-2 procedure revisions, `POST /api/expeditions/{id}/cells/advance`, `POST /api/expeditions/{id}/cells/course`, and `POST /api/expeditions/{id}/cells/encounters/{occurrenceId}/resolve`. Mutations require an expected version and delegate to existing transactional services; HTTP client claims of server-issued `AutomaticRoll` are rejected. The cell-only start route is separate from legacy hex start, permits no implicit preset revision, and does not enable the six-direction workbench UI. A versioned owner-scoped `GET /api/expeditions/{expeditionId}/cell-topology` exposes the actual current polygon and atomic exits; legacy hex and abstract/nonspatial payloads retain their old shape with optional new fields omitted.
- No relational schema change or live tester-data migration is introduced.
- ExpeditionStartService.StartWorldBoundCellsAsync starts generalized world-bound sessions at an authoritative cell center using an owner-authorized pinned procedure selection. HexCrawlService.AdvanceCellExpeditionAsync, ResolveCellExpeditionCourseAsync and ResolveCellExpeditionEncounterAsync enforce owner and expected-version checks and commit through the existing transactional PostgreSQL store. The old hex-shaped HTTP start and workbench routes remain gated for nonhex travel. The new cell-only HTTP start/advance/decision endpoints are backend-facing and are not yet a release-ready integrated player workflow.

## Independent-review gates and known follow-up questions

1. **Shared engine architecture:** challenge the remaining separation between hex-only `AdvanceCore` and `AdvanceCellWatch`. The common watch cadence, encounter occurrence identity, time slicing, lost recognition, DM provenance, time helpers and event collection are shared, but the movement orchestration is typed. Reject the implementation if it has a semantic divergence, invents a second parallel rule engine, or contains an untested resume path.
2. **Geometry and navigation:** inspect arbitrary canonical D-symbol matching, mixed face degrees, partial physical-distance segments, uncalibrated step counts, selected atomic interfaces, double-back, lost veer/recognition, vertex ties, zero-progress loops, and pause-at-watch-end. Unresolved ambiguity must not pick a neighbor. Check exact time, distance and boundary event ordering.
3. **Gameplay composition:** verify that the existing *explicit resolved-input* contract and environment evaluation correctly constrain applicable movement and survival effects. World and cell environment facts, the common movement capability composer, Phase 10/11 resources/effects, foraging, exposure, journey processes and encounter handoffs are not to be replaced with newly invented formulas. Flag any policy that is silently skipped when its pinned module requires a consequence. Cell resource upsert and time-delay effects are directly tested; not every ruleset-specific consequence has a dedicated cell regression yet.
4. **Supported API surface:** the distinct cell-only HTTP start/advance/course/encounter routes are available with pinned version-2 procedures and owner/version checks. The canonical procedure authoring route can produce saved version-2 revisions. The **old six-direction workbench and ordinary hex start remain gated** for nonhex worlds; generalized browser navigation/player map is Phase 19 and image recognition remains in its separately assigned phase. Evaluate request provenance, replay identities, malformed inputs, and stale writes; never silently trust `AutomaticRoll` or claimed `ProcedureDefault` from clients.
5. **Compatibility and data safety:** inspect persisted schema-10 worlds and prior expeditions, pending encounters, saved procedure snapshots, journey/resource/effect state, active watches, world annotations, Knowledge and existing hex/nonspatial contracts. No new relational schema migration was added. Run the exact-head full CI and independent PostgreSQL/container tests.
6. **Release boundary:** WorkChat must return a blocker-graded independent review before any merge authorization. `main` deploys to **dev/testing**, not production; existing tester maps and expeditions must still be protected. Do not reset, seed over, or delete tester data. Expedition deletion is expressly outside Phase 18. No Surveyor work is required here.

## Compatibility and release assessment

Legacy gameplay execution has not been replaced. A bounded generalized **backend/API** start/watch/decision workflow exists, while the legacy browser workbench has deliberately not been repurposed to render nonhex cells. Phase 19 owns that user interface.

**Merge decision: no authorization yet.** This branch is a candidate for independent WorkChat implementation review, not an assertion of production readiness. Any finding about incomplete required Phase 18 semantics remains a blocker until fixed and retested. CI success alone does not authorize merge or deploy.
