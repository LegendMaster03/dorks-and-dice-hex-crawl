## Implemented first slice

- Home spatial world start now loads the selected world's accepted tiling. Existing hex-world q/r fields are converted to a world-space center and sent through `GET /api/overworlds/{id}/cells/containing`; only a unique cell in the matching tiling is accepted. The returned motif cell/translation, not q/r or invented hex-progress state, is sent to `POST /api/overworlds/{id}/cell-expeditions`.
- For generalized worlds the home setup exposes motif cell and lattice translation fields. Saved ruleset revisions are checked through the cell-procedure compatibility endpoint before start. The home selector retains the existing three native geometric hex presets in spatial contexts and permits the original broader preset list for nonspatial journeys. It introduces **no new tiling selector or nonhex presets**.
- The world editor's existing expedition form is replaced by the shared advanced `enhanceExpeditionSetup` form, with saved revisions, three native hex preset recipes, presentation policies, nonhex map-click start selection, compatibility assessment and compatible saved cell-travel ruleset creation.
- Abstract-mapless starts now call `POST /api/expeditions/cells`; nonspatial starts still use `POST /api/expeditions`. The V2 `currentCell` response enters the existing generalized workbench from the same expedition route, including without an authored world. Mapless UI does not offer authored-world location discoveries.
- CanvasMapRenderer now draws the server-authoritative current-cell polygon and party location on an existing hex grid **and** in a mapless session, rather than returning immediately for null world. Mapless viewport initialization and reset retain its actual cell center. The world-bound map still retains its source images.
- The existing generalized workbench uses `GET /cell-topology` and `POST /cells/advance`, `/cells/course`, `/cells/encounters/{occurrenceId}/resolve` for travel, boundary and encounter control, with current-world party/environment/journey/effects/survival subpanels.
- New frontend coverage in `test/phase20-ui-cutover.test.mjs` checks q/r-to-server-cell lookup integrity, rejection of ambiguous/foreign cells, active start-route elimination and mapless render-path guardrails. Obsolete V1 source-contract assertions were replaced where they contradicted the intentional cutover.

The owner rejected reconstructing Phase 15 piecemeal inside a separate geometric UI. **The existing Phase 15 page, Guided/Compact framing, map-first workspace, "Next action" status summary, reusable party/gameplay editors and focused drawer are the presentation authority.** V2 changes the cell geometry and mutation backend beneath those controls. Do not rebuild a second design or restore any old runtime. The original nonspatial/journey interface continues to run independently.

- Spatial sessions use the **same Phase 15 layout and interaction classes**: map as the primary panel, at-table rail, status action cards, GM tools and focusable travel drawer via `openWorkspaceDrawer`. V2 watch inputs are moved into the drawer and returned to an off-screen staging dock on close; moving them does not reset form state or duplicate controls.
- `phase15-cell-action.ts` projects *persisted V2 pauses and qualified course state* into the existing Phase 15 Next-action vocabulary. Explicit encounter, boundary ambiguity, lost-party recognition, paused travel, no-executable-procedure, choose-course and continue/resume states have deterministic unit coverage. The actual movement executor remains the V2 cell watch, not a hex adapter.
- The Phase 15 current-cell navigator consumes `currentPeriodicCellAdjacency(topology)` using authoritative atomic interfaces; map rendering consumes server polygons. Clicking an existing hex grid is translated to a server-qualified cell lookup, not converted into invented runtime progress. Mapless rendering recenters after travel/reload.
- The V2 travel drawer uses `/cells/resolution-helper` for a server-audited automatic roll and supplies the *exact typed* result plus generation ID to `/cells/advance`. Direct DM-input edits, navigator course changes, aggregate changes and reload invalidate the presented generation to avoid stale grants. - The V2 encounter interruption reuses the existing Block Initiative handoff API (by persisted `triggerSequence`) without marking the encounter resolved. The separate V2 `/cells/encounters/{occurrenceId}/resolve` mutation remains the only in-expedition resolution.
- Focused assistant creation now starts spatial mapless sessions through `/api/expeditions/cells` and opens the Phase 15/V2 expedition route, not deleted V1 assistants. Nonspatial cadence uses `/nonspatial/encounters` and nonspatial encounter-resolution endpoints.
- The original V1 hex-only source in `expedition-view.ts`, `expedition-watch-controller.ts` and retired API type definitions is **not revived**. It is still staged for Phase 20.4 source removal after behavior parity and testing. Reusing Phase 15 visual structure does not justify reinstating V1 execution.

## Pre-dev-deployment self-review and cleanup

The owner will manage the dev/testing deployment **after** this code review; there has been no merge or deployment by the implementing agent. The requested review found and corrected:

- **Missing Phase 15 GM actions:** the V2 page now supports teleporting to a selected *server-qualified* cell via `/cells/reposition` and manual reveal/discovery of authored point features or locations in that cell via `/discover`. Teleport is disabled during an active watch or pending encounter; the server additionally guards pending travel-budget charges. The map renderer projects player knowledge from the saved expedition.
- **Map geometry mismatch:** grid-world expedition picking now submits the user's **actual clicked world point** to the server's cell lookup, not the center of an inferred axial hex. It fails closed if the point cannot be uniquely assigned. Exact selected polygons are rendered on existing hex-grid worlds as well as other supported tilings. On a uniquely adjacent selected cell, the corresponding authoritative atomic interface becomes intended travel; ambiguous/distant cells remain inspection-only. Tiling revision changes invalidate stale selected geometry.
- **Automatic helper grants:** editing *any* of the helper's resolution inputs (including navigation DC, modifier and veer) invalidates the current displayed generated result. Picking a different atomic course and modifying the shared party/other aggregates also clear it. The server enforces grant version/audit and exact typed result. The expected physical distance field is populated from the server's movement suggestion when available; the UI never guesses an uncalibrated distance.
- **Watch resume and keyboard behavior:** saved active-watch deliberate-double-back and continue-across-boundaries decisions are restored when reopening a watch, and keyboard focus is preserved across navigator redraws.
- **Test hygiene:** `test/phase20-ui-cutover.test.mjs` now tests V2 action priority, server-qualified map picking, ambiguous adjacency fail-closed, spatial GM API routes, inside-polygon authored subject filtering (including concave polygons), automatic grant invalidation and Phase 15 shell reuse. Unrelated encounter-candidate filtering is explicitly unaffected.
- **Scope discipline:** no retired V1 backend endpoints, hex movement reconstruction, new square/triangle presets or user-facing nonhex selector were added. Preserving unreachable old-client source until Phase 20.4 cleanup is **not** approval to call its removed routes.

For owner-authorized dev deployment and WorkChat testing, use `docs/phase-20.3-workchat-dev-test-handoff.md`. These acceptance scenarios intentionally remain **unverified until executed in a real signed-in browser**.
