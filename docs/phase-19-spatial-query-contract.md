# Phase 19 — world geometry and browser integration status

**Branch:** `feature/tile-crawl-phase-19`. **Status:** Implementation review candidate; independent WorkChat/browser and deployed existing-data acceptance are still required. Do not merge/deploy on the strength of CI alone.

## Authoritative integration completed

- Owner-scoped bounded polygon viewport and containment endpoints delegate to saved `PeriodicWorldTiling`; explicit ambiguity is preserved at shared boundaries. The client renders those polygons, never reconstructs an operational tiling in JavaScript. Qualified cells resolve via the backend.
- The shared `MapSurface` displays polygonal worlds without a source image, handles keyboard center selection, panning, zoom and reset to world origin. Asynchronous selection and viewport requests suppress stale results.
- The existing topology-neutral current-cell navigator receives Phase 18 atomic interface indexes, polygon geometry, and qualified neighbors. A cell expedition uses the normal expedition URL with Phase 18 advance/course/encounter endpoints and does not invent axial coordinates.
- Normal world setup offers square and triangular periodic geometry, optional calibration, and an explicit custom JSON route. The backend accepts any valid independently realizable Euclidean periodic symbol, subject to safe domain limits, not a closed shape allowlist.
- A new saved, editable cell-step campaign procedure can be generated from the existing `simple-fixed-distance` template, pinned to the accepted world topology, with origin/provenance retained; preset definitions and historical revisions are not rewritten. World name updates preserve topology and existing expeditions.
- A read-only owner-scoped procedure compatibility endpoint checks validated D-symbol equivalence via the world's translation cover, executable movement version, and required physical calibration. The generalized expedition start form keeps the Start button disabled until the selected pinned saved revision is confirmed usable, and offers one-click creation of a compatible saved ruleset.
- Polygonal world authoring supports qualified-cell terrain and environment facts and inspecting locations and spatial features against returned polygon geometry. Map drawing/placement still uses world coordinates, independent of any source image.
- Experimental Surveyor-driven image placement now enumerates bounded candidate pixel-to-world affine transforms only after structural equivalence and a full motif-geometry/primitive-lattice/reciprocal-interface check. Source-map authoring previews the generated transforms, asks for explicit selection, and re-runs Surveyor verification on a versioned, single-overworld-aggregate save. World topology and pinned procedure revisions are unchanged. Different translation covers, uncertain raster evidence, and incompatible metrics fail closed to manual placement; automatic topology conversion is not implemented. 
- Source map placement retains the existing exact three-point affine transform and now offers an optional independent fourth landmark. That check measures disagreement in original image pixels without changing the fitted transform or the saved three-point contract. A failed attempted check blocks saving that attempt; clearing points resets it. This is a manual spot check, **not** Surveyor-driven automatic registration or full-raster metric certification. Experimental Surveyor v3 observations remain *read-only* and are compared with the saved world and optional selected pinned procedure.
- Existing hex/Wonderdraft automatic grid analysis and the v2 client remain intact. Generalized patterns do not enter those hex-only controls.

## Authority boundaries and correction safety

Experimental Surveyor observations remain non-authoritative. The server now derives bounded candidate affine registrations by independently comparing motif polygons, a primitive translation-basis correspondence, and **every reciprocal atomic interface** against accepted world geometry. Only a matching, independently proved structure offers image placement candidates. The UI previews alternatives because symmetries can leave absolute orientation/phase ambiguous. Saving a chosen placement re-runs Surveyor and recomputes the candidates; an expected world version and checked transform must match. Existing images, world geometry and pinned rulesets remain unchanged.

For an observed mismatch, the only automatically correctable case is an **unused, uncalibrated generalized world** with no expeditions, registered images, authored locations/features, or environment annotations, and for which the independent metric constructor can realize the observed topology and then verify its pixel correspondence. A correction changes the tiling identity/revision and aligns the chosen source image **atomically in one overworld transaction**. World-bound expedition creation holds a conflicting PostgreSQL SHARE lock and validates current qualified cell identity under that lock. Replacement holds FOR UPDATE and rechecks references before committing. No procedure revision is invented when none is selected. A selected already-compatible immutable revision needs no edit; an incompatible selected procedure is not rewritten and disables direct correction. Legacy hex and Wonderdraft alignment flows are untouched.

A candidate whose translation motif cannot be matched one-to-one, whose scale/phase/metric cannot be verified, or whose geometry has blockers remains advisory; manual registration or a separate world stays available. A successful correction replaces **only previously unused** cell geometry. No schema migration or map-asset mutation is introduced.

Guided world creation now accepts optional repeating-direction lengths and angle, passed as general metric constraints to the same harmonic construction/validation path. Invalid or unsatisfiable geometry fails without creating a world. The human-readable catalog also includes qualified rhombille and descriptive mixed-cell entries, without becoming a pattern implementation allowlist.

## First independent-review remediation

The review at `c4e0be178372a7d5d13c25a62dd2dd9f2e0287b5` found P2 omissions in generalized gameplay editors, keyed discovery location IDs and asynchronous selection, plus a P3 accidental coupling between image registration and optional procedure compatibility. Each now has a corrective implementation and targeted automated regression. The generalized view reuses all five existing gameplay controllers; keyed discovery offers any saved world location, including potential destination cells, and shows whether the pinned procedure schedules checks; authoritative containment is enforced at the actual encounter trigger; two asynchronous selection stages share the same versioned last-click-wins guard; independently verified image registration remains available even when a separately selected procedure is incompatible. The full browser and existing-data acceptance gates below remain open until WorkChat executes them.

## Third review: crossing-before-discovery correction

The second independent review found that restricting keyed encounter options to the cell occupied before the watch could prevent valid discoveries after movement. The selector now offers all saved locations belonging to the world, preserves the selected ID through UI rerenders, and explicitly explains that server containment applies **after movement when the encounter triggers**. The retained in-place server containment check rejects a location in the wrong cell. A new PostgreSQL HTTP test crosses a real cell interface, triggers at the end of the watch, verifies the destination location, verifies that choosing a starting-cell location for the same crossing is rejected without persistence, and confirms encounter-resolution replay rejection and durability across restart. The previous stationary discovery test also remains.

**Remaining operational gates are unchanged:** this repository-only remediation does not constitute signed-in browser acceptance, real Surveyor imagery/registration acceptance, or existing tester-data restart acceptance. None is marked passed. Follow the updated WorkChat handoff before any merge or deployment.
