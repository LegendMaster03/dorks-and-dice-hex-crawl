# UI Readability Coverage Matrix

This matrix records the presentation coverage for the comprehensive expedition readability pass. The current catalog contains **12 presets** and **19 authoring modules**. Presets remain compositions of generic modules; no presentation behavior branches on preset identity.

The layout follows the same design principle across authoring and play: compact aligned facts for scanable state, roster or ledger rows for repeated entities, progress indicators only when authoritative bounds exist, stage sequences for journeys, and focused resolution blocks for actions that require a decision.

## Movement composition contributor coverage

The movement ledger is generic over the authoritative contributor projection and supports every current contributor kind: Participant, Mount, Vehicle, Load, TravelMode, TerrainRoute, Environment, PersistentEffect, and DmOverride. Each row shows source, operation, value or symbolic value, and whether the contributor applied. The summary distinguishes authoritative base/reference use, unresolved inputs, retained but unapplied contributors, and applied DM overrides. Spatial expeditions expose it in the focused Movement workspace; nonspatial procedures with movement composition expose the same ledger in the party/activity workspace.

## Representative visual review scenarios

The Phase 15 rendered review matrix contains **63 representative scenarios**. Procedure evidence uses a feature-rich custom fixture containing all **19 modules** rather than a `time.interval`-only fixture. It renders Compact at desktop width and inside a measured **390-pixel content container**, renders the exact procedure reference with all 19 modules and all exact-parameter disclosures, and retains Advanced/JSON coverage. Raw Chrome headless currently reports a 500-pixel browser viewport for requests below that minimum; the capture artifacts now record both requested window width and measured viewport width instead of claiming native 390-pixel viewport coverage.

Runtime evidence includes the all-nine-kind spatial movement composition, nonspatial movement composition, pre-pending encounter scheduling for native PerWatch, native PerDay, and contextual-only travel-and-camp rules, and a survival/resources/effects workspace with counted/abstract/supply-die/external-manual inventory records, effective environment and exposure progress, foraging and camping summaries, and multiple active effects. Narrow ledger evidence uses a 390-pixel content container, includes the longer target name `Cora Longriver`, and asserts that core short labels such as `Fatigue` and `Exhaustion` remain single-line while tables scroll internally. Existing scenarios continue to cover partial progress, navigation/boundary resolution, forced travel across participant/party/mount/vehicle scopes, journey pending/consequence states, abstract spatial play, light/dark themes, embedded width, tablet, and narrow/mobile widths.

Journey scenarios deliberately store stage definitions as `arrival, approach, pass` while the authoritative `stageOrder` is `approach, pass, arrival`; the rendered assertion requires the authoritative label order. The matrix remains representative rather than an exhaustive Cartesian product. Exact configuration remains available through Advanced/JSON and the reference's Exact parameter detail disclosure.

## Regression evidence

The semantic presentation test uses representative real parameters for every catalog module and asserts each module's expected semantic section keys. Generic fallback output can no longer satisfy that coverage test. The journey-order unit test independently shuffles stage definitions and verifies `stageOrder` resolution before DOM rendering. Contextual encounter schedule tests verify that `encounters.schedule` remains discoverable when native cadence runtime is absent, and the rendered matrix independently covers contextual-only, PerWatch, and PerDay encounter presentation.
